# LGTV Companion Linux reimplementation plan

Port LGTV Companion 5.7.0 at commit `a37d054` to Rust. Preserve automatic TV management, the desktop configuration and diagnostic workflows, both command-line execution modes, the scripting API, and the installer and updater workflows. Use the checked-in Windows implementation as the behavioral reference, including the three end-of-stream modes. Define parity per Linux desktop and TV firmware combination. Linux desktop capabilities and TV firmware permissions determine which integrations can run on a given machine. [Windows overview](../README.md) · [Version definition](../Common/common_app_define.h)

## Architecture and initial support targets

Start with systemd/logind Linux on x86-64, one active local seat, and LG webOS TVs on the local IPv4 network. Use Xorg as an early end-to-end reference, and qualify GNOME Wayland, KDE Plasma Wayland and Sway individually. Ship headless TV control and host lifecycle automation through the same system service. Use explicit mappings for multi-seat hosts if supported later. These are proposed implementation and release targets.

| Component | Responsibility |
| --- | --- |
| Shared Rust libraries | Typed config, legacy importer, command registry, wire payloads, discovery, wake and pairing, plus a deterministic policy reducer that takes normalized host/session events and emits per-device actions. |
| `lgtv-companiond` | System service with a dedicated service account. Own device state, scheduling, registration keys, configuration revisions, command IPC, and logind subscriptions. Run before login and independently of the GUI. |
| `lgtv-companion-session` | Run in the graphical session. Report active outputs, display power, input idle/activity, window and inhibitor state, and stream activity. Implement visible diagnostic and hidden startup modes. |
| `lgtv-companion` | Native settings application and asynchronous command entry point. Share daemon command and settings contracts. |
| `lgtvcli` | Ordered, response-producing command client with direct TV transport when the daemon is unavailable or the user selects direct mode. Daemon-only features return an actionable error in direct mode. |
| Update integration | Query the Linux release feed, display release notes and notifications, and delegate installation to the system's authorized package backend. |

Use a Cargo workspace. Candidate libraries are Tokio, serde/serde_json, tokio-tungstenite with rustls, socket2, rtnetlink, zbus, tracing, x11rb, wayland-client and gtk4-rs. Select and pin versions after the protocol and desktop spikes. Keep the policy and wire types independent of D-Bus, window managers and widgets. Use one serialized worker per TV with bounded queues, request deadlines and cancellation. Run workers concurrently for daemon dispatch and preserve the documented serial ordering for console batches.

## Device discovery and webOS control

| Windows behavior | Linux implementation and acceptance check |
| --- | --- |
| Scan for LG devices, append or replace, refresh an existing device's IP by MAC, and allow manual setup | Prototype SSDP/UPnP discovery on each eligible LAN interface and validate candidates against LG device metadata. Resolve MAC and subnet through route/address/neighbor data where available. Display missing MACs for manual completion. Stage changes for Apply, deduplicate by normalized MAC, and preserve the current list when a replacement scan yields no usable result. Test two interfaces, changed IP, duplicates and no results. |
| Per-device name, IDs, IP, multiple MACs, interface selection, subnet, automatic management, and test/on/off actions | Use a stable internal ID plus compatible `DeviceN` selectors and editable friendly names. Resolve the chosen Linux interface at runtime and infer a default route when unspecified. Validate HDMI 1–4 and delay 0–30 seconds. Test disabled automation with working manual controls and independent multi-TV settings. |
| Wake-on-LAN in limited broadcast, direct IP, subnet broadcast and automatic modes | Verify the 102-byte magic packet, UDP port 9 and one-second repeat interval with packet fixtures. Default to a 40-second wake timeout, adjustable from 5 to 100 seconds. Derive broadcast and source address from the selected interface and route. Test direct IP to a sleeping TV with an empty neighbor cache. Prototype a narrowly scoped privileged neighbor helper for that case, keyed to the configured on-link TV, with bounded lifetime and ownership-aware cleanup. Broadcast modes and ordinary TV operations run without that privilege. Test multiple MACs, multiple NICs, and failure during pixel refresh or network loss. |
| Registration, pairing prompt, saved keys, key reset, and WOL enable attempt on successful first pairing | Port the registration manifest and paired/unpaired exchange. Persist keys atomically and expose explicit reset/re-pairing. Use WSS 3001 by default and offer WS 3000 for devices configured for it. Verify actual firmware certificate behavior and implement per-device trust or pinning with a visible re-trust flow for changes. Keep credentials out of logs and diagnostics. Test rejected prompts, invalid keys, reset, and restart without re-pairing. |
| Connection modes off, persistent, and persistent with keepalive | Port the separate connection lifetimes, reconnection and application-level polling behavior. Match request IDs to replies and bound retries. On a lost reply, query state before repeating a power toggle. Exercise disconnects, malformed responses, keepalive failures, and cancellation. |
| Power on, power off, screen blank/unblank, HDMI safety, and optional speaker mute | Distinguish standby, active, and screen-off with emitters disabled. Wake and verify active state. Check the TV's foreground HDMI before automatic off or blank when enabled. Honor forced actions and optional post-wake HDMI switching with its configured delay. Port mute/unmute on the relevant blank/unblank path. Test a TV on another HDMI or in a native app, plus delayed HDMI work superseded by a newer host event. |
| SSAP, Luna settings, app launch/close, remote buttons and service operations | Port payload builders and the secondary pointer-input WebSocket, including button sequences, the FreeSync information overlay and the notification bridge used for Luna calls. Preserve device-provided errors and the original distinction between a reply and an accepted command with no useful response. Verify supported and rejected commands against stock firmware samples. |

The original scanner uses Windows device discovery records. Validate SSDP coverage on real TVs early and retain the manual workflow for models or networks where discovery yields incomplete data. The TV needs network wake enabled. Same-LAN reachability, standby behavior, and the pixel refresh window remain physical constraints. ## Automatic management

| Trigger or policy | Linux mapping and expected behavior |
| --- | --- |
| Boot, resume and display on | Normalize host lifecycle separately from display state. Windows boot and resume initialize state and an eligible display-on transition drives the TV wake. Reconcile against the first effective display snapshot or the opted-in saved topology at the greeter. Account for link readiness, session handoff, auto-wake with displays still asleep, and duplicate resume/display notifications. |
| Suspend and hibernate | Subscribe to logind `PrepareForSleep` and use a bounded delay inhibitor. Issue automatic TV off while the link is available and release the inhibitor on completion or deadline. On resume, reacquire the inhibitor, discard stale work, and reconcile the network and active outputs. Test suspend, hibernate and an unattended wake. |
| Shutdown, reboot and timing | Prefer logind `PrepareForShutdownWithMetadata` when available. Treat reboot-like actions as reboot and retain the TV state. Power off managed eligible TVs on host power-off and on the Windows-equivalent unknown shutdown outcome. On older hosts, validate an early, typed systemd shutdown-intent hook with usable network ordering, or expose the unknown-shutdown behavior. Deduplicate metadata and legacy signals. Offer early, default and delayed dispatch within the actual inhibitor and network budget. Test from the desktop and `systemctl`, plus cancellation and normal service restart. |
| Host display on/off/dim and screensaver | Observe desktop power separately from app idle, connector enablement and session lock. Host off sends automatic TV off. Ordinary dim is observational. Dim with the screensaver active follows the original off behavior. Display on wakes eligible TVs, subject to topology and streaming. |
| User Idle Mode | Keep a separate inactivity timer with the Windows 10-minute default and 1–240 minute range. Idle blanks eligible screens. Activity restores them. Support forced idle/unidle, ignored keys, controller input, optional suppression of the system-wide fallback, and the speaker mute option. |
| Idle exceptions | Preserve global fullscreen and video/display-wake-lock rules, including foreground/fullscreen qualifiers, and per-process rules for running, foreground, fullscreen and owning a display wake lock. Use session-local app identity and PIDs where available, including executable names and app IDs. Surface unobservable rules in diagnostics. Treat blanket inhibitor signals as aggregate evidence only. |
| Monitor topology | Follow enabled display paths, including clone mode. Map TV IDs to active outputs using EDID identity and connector hints, with a guided identify/confirm flow for duplicate or missing identifiers. Debounce changes and distinguish a known empty topology from an unavailable snapshot. Save the validated active set when the greeter/boot option is enabled, warn on stale mappings, and avoid switching TVs on while host displays are off. Test clones, identical TVs, inactive but connected outputs, and docking. |
| Remote streaming | Aggregate Sunshine, Apollo, Steam Remote Play, and remote desktop adapters by source/session. Track first connect and last disconnect. Capture the Windows detector delays of 10 seconds on connect and one second on disconnect in policy fixtures and cancel stale pending transitions. Use explicit `-streaming_connect` and `-streaming_disconnect` hooks for hosts that can invoke them. Ensure a server process alone cannot count as an active stream. Preserve the Windows intent of GameStream/NVIDIA event and RDP detection through applicable Linux sources, with hook-based integration for hosts without an observable session source. |
| Streaming end | While host displays are on, connect powers off or blanks managed TVs, subject to HDMI safety. In power-off mode, capture each TV's state before the action. On last disconnect, support power on, keep off, or restore only TVs previously known on. Active and screen-off both count as on for capture. Blank mode always restores via the wake/unblank path while host displays are on. If the stream had powered off TVs and none will be restored, request desktop display power-off through the session backend so subsequent input can wake them. Test unknown state, mixed TV state, second streams, out-of-order disconnect and suspension during a stream. |
| Automatic management overrides | Keep config enablement separate from temporary `-autoenable`/`-autodisable` changes. Clear temporary overrides at daemon restart. A forced power or TV command remains independent of that automation switch. |

Keep app idle, host display power, topology, session ownership, stream state, and TV state separate in the reducer. Preserve the actual source gates for each event. In particular, Windows suppresses idle/busy and topology actions during streaming, while normal shutdown still attempts power-off. Correlate pre-stream power snapshots and queued work to each stream generation. Debounce desktop events without delaying shutdown traffic beyond its budget. ## Command line and scripting contracts

Build a machine-readable registry by reconciling `Docs/Commandline.md`, the hard-coded dispatch branches in both executables, the generated command table and the button list. Record command and alias, supported execution modes, argument types/ranges, payload builder, expected response and example. Make registry coverage a release check so every present command is exercised, including source-only behavior and documented differences between executables. - Cover power and screen control, app management and streaming hooks, HDMI selection/label/icon and HDMI-scoped modes, audio and volume, virtual buttons and FreeSync, service menu and TPC/GSR, settings queries, picture/network/other settings, Flex bend/curvature presets, raw SSAP and app launch/close with JSON parameters, and arbitrary picture, other and options settings.
- Preserve case-insensitive command and device matching, case-sensitive payloads, optional targeting of all configured TVs, multiple targets, and multiple commands in one invocation. Parse Linux argv with registry-aware arity so negative numbers and JSON reach validators as values. Verify labels with spaces, Unicode and hyphens, aliases, unknown targets and ambiguous names.
- Support asynchronous submission and ordered response modes. Capture the Windows console's compact, friendly and key-filtered output shapes, mixed-format batches, errors and multi-TV ordering as golden fixtures. Keep diagnostic output on stderr and document exit-status behavior for Linux scripts and partial failures.
- Replace the Win32 named pipe with a permission-controlled Unix socket under `/run/lgtv-companion/`. Use framed UTF-8 JSON with versioned methods, request IDs, bounded messages and separate internal session reporting permissions. Authorize peers by UID/group and confirm active-session ownership through logind. Preserve the opt-in external event feed with `SYSTEM_DISPLAYS_ON`, `SYSTEM_DISPLAYS_OFF`, `SYSTEM_DISPLAYS_OFF_DIMMED`, `SYSTEM_USER_IDLE`, `SYSTEM_USER_BUSY`, `SYSTEM_SUSPEND`, `SYSTEM_RESUME`, `SYSTEM_REBOOT` and `SYSTEM_SHUTDOWN`. ## Implementation milestones

| Milestone | Deliverable and gate |
| --- | --- |
| 1. Capture behavior and resolve platform risks | Build source-derived command, preference and policy matrices and capture Windows golden fixtures using mock TVs or sanitized traces. Spike logind ordering, WSS pairing, SSDP, direct-IP wake, and observability of idle/display/inhibitor signals on the target desktops. Record each capability as native, desktop extension, hook-based, or unavailable on the tested version. |
| 2. WebOS library and direct CLI | Implement discovery, config decoding, registration, transport, WOL and the complete command registry. Pass mock-TV golden fixtures and exercise real-TV power, HDMI, audio and a setting query. |
| 3. Daemon and lifecycle | Implement device workers, permissions, persistence, local IPC, scripting, and host power automation. Pass fault injection for link loss, dropped replies, simultaneous clients, stale work and daemon restart. Verify real shutdown, reboot, suspend and resume in a VM plus timing and delivery on physical hosts. |
| 4. Desktop behavior | Implement Xorg and qualify the named Wayland adapters with the same scenario suite. Verify idle exceptions, controller activity, topology mapping, greeter restoration, streaming modes, and host display synchronization. For each supported release desktop, test the entire path from original-equivalent input to TV action. |
| 5. Settings, packaging and release | Ship GUI, updater, installer and Linux scripting docs. Run clean install, upgrade, uninstall and Windows migration exercises. Publish the supported distro, desktop, compositor and TV firmware matrix with the mechanism and limitations for each feature. |

Use reducer tests for overlapping events and exact per-device actions. Use an instrumented WS/WSS test server for pairing and protocol tests, UDP capture for WOL, and integration tests for socket permissions, restart, configuration recovery and CLI stdout. Hardware acceptance should include Ethernet and Wi-Fi wake, multiple TVs and NICs, mixed firmware generations, cold boot to greeter, screen blanking with optional audio mute, external-source HDMI safety, display hotplug, sleep/wake and overlapping streams. Exercise firmware-sensitive service settings via mocks and use an explicitly designated test TV for settings that need hardware verification.

Release full parity for a desktop only after all applicable matrix rows pass, including command inventory coverage, Windows import, session behavior and package lifecycle. The main open qualification items are old-systemd shutdown classification, direct-IP WOL after neighbor expiry, per-application inhibitors and ignored-key visibility on Wayland, and reliable host display power control after a stream. Track equivalent hooks and native coverage separately in the published matrix so users can tell which behavior their setup provides.
